# 論文との対応と検証の範囲

本パッケージは Rota らの **Illuminant-Adaptive 3D Lookup Tables for Camera
Color Correction**（arXiv:2607.11681v2）の C²LUT を本文から独立に実装したものです。
著者の実装との同一性を主張するものではありません。2026 年 10 月 30 日の確認時点で、
著者の公開先には採択後にコードを公開する旨の README のみがありました。

- [論文本文](https://arxiv.org/html/2607.11681v2)
- [著者の公開先](https://github.com/claudiom4sir/C2LUT)

## 対応環境と Notebook の実行

サポート対象は **Linux** です。CI では Ubuntu 上の Python 3.11・3.12・3.13 で
ネイティブ拡張のビルド、数値検証、型検査、配布物の作成を確認します。
macOS と Windows はサポート対象に含めません。ビルドには C++17 対応の
コンパイラが必要です。

`notebooks/synthetic_color_correction.ipynb` では、ダミーデータの生成から学習、
補正前後の色と誤差の可視化までを一通り実行できます。リポジトリのルートで
次のコマンドを実行してください。

```bash
uv sync --locked --extra notebook
uv run --locked --extra notebook jupyter lab notebooks/synthetic_color_correction.ipynb
```

ブラウザを開かずに Notebook 全体を検証する場合は、次のコマンドを使用します。
CI でも Python 3.12 上で同じテストを実行し、新しいカーネルで先頭から最後まで
実行できることを確認します。

```bash
uv run --locked --extra notebook pytest -q -m notebook
```

Notebook が使う人工等色関数と参照光は、下記「人工データの確認で分かること」で
説明する XYZ 相当の合成系です。色見本はこの合成系を画面上で比較するための表示であり、
実在するカメラの測色精度や論文のベンチマークを再現したものではありません。

## 数式と処理の対応

| 論文の箇所 | 処理 | 実装で扱う内容 |
|---|---|---|
| 式 (1)–(3) | 分光積分 | 光源・反射率・カメラ感度から raw と白色点を求め、参照光源下の三刺激値を教師にする |
| 式 (4) | 白色化 | raw を同じ尺度の白色点で成分ごとに除算する |
| 式 (5) | 光源特徴 | 白色点の R、G を RGB 合計で除した 2 成分 |
| 式 (6) | 基底の合成 | MLP の非負・合計 1 の重みで Tucker コアを合成する |
| 式 (7) | LUT 再構成 | 色因子と 3 個の空間因子で、出力色 × R × G × B の LUT を生成する |
| 式 (8)–(11) | 画素変換 | 白色化した入力に三線形補間を適用する |
| 式 (12)–(14) | 学習目的 | Lab の ΔE76 と LUT の平滑化損失を組み合わせる |

光源に応じた LUT の生成と、各画素への適用を分離します。同じ光源の画像に適用する
LUT を再利用でき、画素処理には nanobind 経由で C++ を使用できます。
このモデルは、空間的に一様な光源と既知または別手法で推定した白色点を前提とします。
光源推定、RAW の復号、デモザイク、ガンマ補正をこの色変換に含めません。

## 本文の指定と実装上の補完

本文 §IV-B の主要構成は LUT 解像度 65、Tucker 階数 17、基底数 12、
隠れ幅 32 の MLP です。`ModelConfig()` はこの規模を既定値にしています。
CPU で実行するコマンドの既定値は、人工データの動作確認向けに小さくしています。

| 項目 | `ModelConfig()` | 学習コマンドの既定値 |
|---|---:|---:|
| LUT 解像度 | 65 | 9 |
| Tucker 階数 | 17 | 4 |
| 基底数 | 12 | 4 |
| 隠れ層 | 幅 32、1 層 | 幅 32、1 層 |

MLP は ReLU と softmax を使います。ReLU は本文に指定がないため、本実装での
選択です。Adam と cosine による学習率減衰を使用しますが、コマンドの既定値
500 更新・初期学習率 0.003 は人工データ用です。論文の初期学習率は 0.001、
学習期間は「収束まで」であり、更新回数は未記載です。

**初期化の対称性。** 本文には、恒等 LUT から得た同一の基底コアと一様な
初期混合重みが記載されています。これを厳密に適用すると、全コアへの勾配が等しく、
softmax への勾配はゼロとなります。決定的な更新ではこの対称性が維持され、
光源ごとに異なる LUT を学習できません。

`ModelParameters.identity` は、定数関数と一次関数を含む基底を QR 分解で直交化し、
恒等変換を表す Tucker コアを構成します。大きな恒等 LUT を作ってから数値的に
圧縮する処理は不要です。各コアに乱数の摂動を加え、基底方向の平均を差し引くことで、
一様な softmax 重みのもとで摂動が相殺し、初期 LUT を浮動小数点誤差の範囲で
恒等変換に保ちます。摂動を生成する標準偏差の既定値は `1e-3`、学習コマンドでは
`0.03` です。`perturbation=0` で対称な初期状態も作れます。この対称性への対策は、
本文に基づく実装上の判断で、著者のコードで確認した仕様ではありません。

**平滑化。** 式 (13) は軸方向勾配の L2 ノルムの和ですが、離散差分の定義、
要素平均、平方、画像やバッチに関する集約は説明されていません。
本文の係数 100 は、異なる正規化の損失にそのまま移植できません。
`TrainingConfig` の既定値は `smoothness_mode="mean_squared"`、
`smoothness_weight=0.1` です。各方式を次のように定義します。

- `mean_squared`：隣接格子の差を二乗し、バッチ・出力チャネル・その軸に沿った
  全隣接格子で平均した値を、R・G・B の 3 軸について加算します。
- `frobenius`：各 LUT の各軸差分について Frobenius ノルムを計算し、
  3 軸を加算してからバッチを平均します。

どちらも格子間隔では除算しません。後者は式 (13) の L2 ノルムに沿った選択肢ですが、
著者の集約方法が不明なため、いずれも著者の実装との完全な一致は確認できません。

**尺度と適用範囲。** 分光レンダラは台形積分を使い、raw と白色点を共通の尺度で
計算します。教師の三刺激値は参照光源下の完全拡散反射面の Y が 1 となるように
正規化します。推論 API は白色化後の入力を既定の `out_of_range="clip"` で
`[0, 1]` に切り詰め、`out_of_range="raise"` では範囲外をエラーにします。
出力の三刺激値は切り詰めません。
raw のみを倍率変更した場合の露光不変性は、非線形 LUT の性質として保証されません。

## 色変換と評価指標の数値規約

`c2lut.color` は NumPy float64 を使い、入力末尾の軸を 3 成分として検証します。
NaN、無限大、不適切な形状を拒否し、入力配列を変更しません。2 入力の指標は先行軸を
NumPy の規則で拡張し、1 組の比較では 0 次元配列を返します。

- `xyz_to_lab` の既定白色点は D65 の `(0.95047, 1, 1.08883)` です。
  XYZ は白の Y が 1 となる尺度を想定し、別の白色点を明示できます。
  負の XYZ も標準の線形枝で扱い、値域の切り詰めや色順応を行いません。
- `delta_e76` は Lab 上のユークリッド距離です。
- `delta_e2000` は CIEDE2000 を `kL = kC = kH = 1` で計算します。
  色相差 180 度の分岐では 1e-12 度以内の丸め誤差だけを同一境界として扱います。
  元の式にある不連続性を平滑化しません。
- `angular_error_degrees` は XYZ ベクトル間の角度です。角度が未定義となる
  ゼロベクトルについて、両方ゼロなら 0 度、一方だけゼロなら 90 度と定義します。
  非ゼロの入力では尺度を正規化し、外積と内積から `atan2` で計算します。

ΔE00 は [Sharma らの独立した補足試験データ 34 組](https://hajim.rochester.edu/ece/sites/gsharma/ciede2000/)
を用いて、丸められた期待値との許容誤差 5e-5 で照合します。CIE の等色関数や
D65 の数値表は、このパッケージに同梱しません。

## 人工データの確認で分かること

人工データは再現可能な条件下で、データ生成、学習、モデル保存・読込み、LUT 生成、
C++ による推論という一連の処理を確認するために使用します。補間については、恒等変換や
解析的に分かる変換と照合することで、別実装同士の一致だけに依存しない検証ができます。
学習後の評価には、学習に使わない入力と光源を用い、改善量と基準を記録します。

付属の人工分光系は人工等色関数を使用する **XYZ 相当の合成系** です。
`make_synthetic_splits` は 400–700 nm を 5 nm 刻みの 61 波長で扱い、
非負のガウス関数から人工センサー感度と人工等色関数を作ります。参照スペクトルは
一定値です。この参照光で完全拡散反射面の三刺激値が `(0.95047, 1, 1.08883)`
になるように人工等色関数を調整しますが、CIE の実測等色関数や標準 D65 の分光分布
を用いた計算ではありません。論文の 31 波長による設定とも異なります。

光源と反射率はそれぞれ約 60%・20%・20% に分け、同じ光源 ID または反射率 ID が
学習・検証・試験の間をまたがないようにします。分光生成式自体は LUT モデルに依存
しないため、教師値を推論モデル自身で作った比較にはなりません。

その値に Lab や ΔE の数式を適用した結果は、数値処理と学習の動作を確認する指標です。
実在するカメラの測色精度や、実機の CIE 色差性能を証明するものではありません。
分光レンダラに実際の感度・等色関数・光源を入力できることと、その測定値による
検証を実施したことも区別してください。

この検証を、論文の実測光源と補間光源を合わせた 1,473 件、41M/KAUST/MCC、
3 種のカメラでのベンチマーク結果の再現とは呼びません。RGB への縮約では分光情報が失われるため、
一般的な分光データに対する完全な復元も保証されません。

## 構成から算出できる記憶量

本文どおり 2→32→12 の MLP と、解像度 65・階数 17・基底数 12 を使う場合、
バイアスを含む係数数は 180,684、float32 の重みは 722,736 bytes です。
再構成した 3 出力の LUT は別に 3,295,500 bytes を必要とします。
本文 §IV-H の重み 726.96 KB とは一致しないため、成果物の記憶量は自身の配列から
算出する必要があります。この理論値には Python オブジェクト、一時配列、
学習時の勾配・最適化器の状態を含めません。本パッケージの NumPy パラメータは
float64 のため、同じ形状なら配列本体の記憶量は上記 float32 値の 2 倍です。
